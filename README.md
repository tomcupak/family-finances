# Family Finances

A self-hosted household budget app: meter readings, expenses, income, savings goals and taxes, one month at a time. It answers "how much do we have left this month?" and "what do we have to pay, to whom?".

> The UI is in **Czech** and the domain is Czech-specific: CZK, Czech bank accounts and QR Platba (SPAYD), Czech public holidays, OSVČ (self-employed) taxes and insurance.

It is built for a single household: one shared API token, no user accounts. "Accounts" in the app are separate budgets (e.g. family / business), not users.

## Features

- **Overview**: per month, what is paid in it. That is income (for the previous month), expenses by category incl. tax advances, savings contributions, and what remains to spend. Quick actions confirm savings contributions.
- **Meter readings** for electricity (high/low tariff), water and gas. Sheets hold either cumulative meter states or per-period consumption (e.g. an EV charger). There is a bulk entry form for all meters (made for a phone) and a consumption chart by day / week / month / year.
- **Expenses**: one-off, monthly, quarterly or yearly, in categories, with an optional end month.
  - Expenses linked to a meter sheet are computed as consumption × monthly unit price + fixed fee. A month without its own price inherits the last one.
  - Corrections handle overpayments and underpayments, e.g. SPOT-price electricity billing.
- **Payees and payments**: Czech account number (checksum validated) or IBAN, plus an optional variable symbol. Per month you get a payment summary per payee with a **QR Platba** code and a "paid" mark.
- **Income**:
  - Employee: gross / net salary.
  - Self-employed: hourly rate, working days from the Czech calendar, vacation days, the expected invoice. The app tracks a vacation savings balance and the remaining vacation allowance.
- **Savings goals**: target amount by a month, with the required monthly contribution, the expected balance and confirmation of contributions.
- **Taxes (OSVČ)**: a yearly tax return calculation (income tax, social and health insurance, discounts) with configurable constants. Monthly advances, settlement (amount to pay or refund) and closing the year, which locks that year's income.
- **Installable** as a PWA, works on a phone. A privacy curtain hides the numbers when the window loses focus.

## Tech stack

| | |
|---|---|
| API | [NestJS](https://nestjs.com/) 11, [Drizzle ORM](https://orm.drizzle.team/), PostgreSQL 17, Swagger / OpenAPI |
| Web | React + [Vite](https://vite.dev/), hand-written CSS, API client generated by [orval](https://orval.dev/) |
| Tests | Jest, unit tests plus DB integration tests against a real Postgres |
| Deploy | a `.deb` package with a systemd service (bundled Node.js) and a static SPA behind Nginx |

Monorepo layout: `apps/api` (the HTTP layer), `libs/domains` (business logic per domain), `libs/database` (schema + migrations), `libs/shared` (helpers), `web/apps/family-finances` (the frontend). Architecture and conventions are described in [CLAUDE.md](CLAUDE.md).

## Getting started

Requirements: Node.js **24.10+** (see `.nvmrc`), npm 11.6+, and Docker or Podman.

```bash
npm install
docker compose up -d        # or: podman-compose up -d (Postgres on localhost:10400)
npm run dev                 # API on :3000, web on :5173
```

Open http://localhost:5173 and log in with the dev token **`dev-token`**. The API applies migrations on startup. Swagger is available at http://localhost:3000/swagger.

The API reads its configuration from environment variables. The defaults work for local development; all variables are listed in [`.env.sample`](.env.sample). `npm run env:init` copies it to `.env` (it won't overwrite an existing one).

### Useful commands

| Command | |
|---|---|
| `npm test` | Jest (unit + DB tests; needs the Postgres container, creates its own `family_finances_test` DB) |
| `npm run lint` / `npm run lint:web` | ESLint for the API / web |
| `npm run db` | generate a Drizzle migration after changing `libs/database/src/core/schema.ts` |
| `npm run orval:web` | regenerate the web API client from the running API's Swagger |
| `npm run build` / `npm run build:web` | production builds |

## Deployment

See [scripts/deploy/README.md](scripts/deploy/README.md): a one-time server setup (users, PostgreSQL, Nginx + TLS, secrets) and `npm run deploy`. The target server is configured in your local `.env` (`DEPLOY_TARGET`, optionally `DEPLOY_SSH_KEY`), never in the repository.

In production the API refuses to start without a real `API_TOKEN` and `POSTGRES_PASSWORD`. The dev defaults above are public.
